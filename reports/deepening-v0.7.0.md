# LLaVA 参数高效微调与问题驱动区域阅读（v0.7.0）

本轮在 MacBook MPS、系统 Python/PyTorch、VS Code 集成终端运行。新增训练规模和问题驱动区域阅读消融；所有原始预测、区域、OCR、源码快照与权重保留在本机。

## 新训练与保留评测

122 道训练题来自 64 个源文档，包含上一版的 59 题；新验证 24 文档，新保留评测 64 文档。按源文档、问题 ID、图片哈希排除已知开发/评测文档。验证 NLL 选择训练轮次，保留集不用于选模型。

| 配置（均为整页 512） | 完全匹配 | ANLS 风格 |
|---|---:|---:|
| 原模型 | 38/64 | 0.8176 |
| 此前 59 题 LoRA | 37/64 | 0.7940 |
| 本轮 122 题 LoRA | 37/64 | 0.7940 |

两轮共 62 次更新，选择第 2 轮；验证答案 token NLL 从 0.9503 到 0.8297。验证集 EM 从 7/24 到 11/24。验证改善不保证保留集生成改善。

参数核验：48/48 个 B 矩阵非零，保留集 24/64 个原始回答变化。模型确实发生更新，效果仍以配对评测为准。

旧、新 adapter 哈希不同；两者之间 3/64 个原始回答不同。评分是否变化见逐题配对 JSON，不把相同分数误写成相同权重。

训练统计与配对区间见 [训练 JSON](expanded-sft-v0.7.0.json)。旧、新 adapter 的验证集和 checkpoint 选择不同，因此两者比较不能解释为纯数据量因果实验。64 文档来自有标签的 validation 镜像，候选池有限，不是官方盲测。

## OCR 辅助消融：同一 LoRA、同一开发集

EasyOCR 的 PyTorch CRAFT/英文识别器在 CPU 提取文字与四边形；区域选择使用 PyTorch BM25，匹配问题词与相邻文字行，返回完整宽度的横带。每带最多八行、128 个文字 token，最多两带。无匹配退回整页。不读取答案选区域。

| 方法 | 完全匹配 | ANLS 风格 | 单请求流程中位秒 |
|---|---:|---:|---:|
| whole | 12/20 | 0.8421 | 2.04 |
| question-only | 0/20 | 0.0395 | 0.25 |
| ocr-only | 1/20 | 0.1155 | 12.40 |
| ocr-crop | 12/20 | 0.7933 | 13.10 |
| whole-ocr | 8/20 | 0.6962 | 14.51 |
| shuffled-ocr | 12/20 | 0.8421 | 13.96 |

question-only 使用同一语言模型且无图片，ocr-only 只加入检索文字；whole-ocr 同时输入整页与文字，shuffled-ocr 用另一问题检索文字再回答原问题。各组文字长度不同，不能宣称 token 完全匹配。

检索审计：原问题在 16/20 页返回非空候选，错配问题仅 3/20 页。错配控制多数退回无文字输入，不能把差值解释成同等文字预算下的问题相关性收益。没有证据框真值，非空比例不是证据召回率。本轮原问题上下文发生 token 上限裁剪的页数为 0/20。

OCR 结果在实验中缓存，表中流程时间仍加回该页 OCR 实测耗时；CPU OCR 当时与 MPS 训练并行，时间受到资源争用影响，仅供成本透明，不作速度基准。全部时间排除权重加载和裁剪文件保存。

## 结论边界与复现

区域/OCR 只在已查看的 20 文档上开发，不代表独立集增益；没有真实证据框，因此不报告 IoU 或已验证 grounding。新保留集评测后也成为已知数据，下一轮调参需新留出文档。ANLS 为本项目风格实现，尚未核验官方 evaluator 等价。配对 bootstrap 仅作探索分析，未校正多重比较。
