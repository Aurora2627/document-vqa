# 真实文档开发集实验 — v0.3.0

2026-10-09，全部在 VS Code 集成终端使用系统 Python、PyTorch 与 MacBook MPS 完成。模型为固定版本的 LLaVA-OneVision-0.5B，基座 Float16，无 adapter，greedy 生成，最多 64 个新 token。模型 revision 与 v0.2.0 一致。

## 数据和实验设计

使用 [LMMs-Lab 的公开 DocVQA 镜像](https://huggingface.co/datasets/lmms-lab-encoder/DocVQA)，配置 DocVQA、validation 划分。取 viewer 首批 100 条记录中每个不同 UCSF 源文档的第一道题，保留前 20 个不同源文档，共 20 道题。数据不是合成发票，也不是从结果中挑选答对样例。该顺序子集仅用于开发诊断，不代表全验证集分布，不能作为独立测试集。

下载前后镜像仓库 revision 均为 `539088ef8a8ada01ac8e2e6d4e372586748a265e`。viewer 接口不锁定 revision，因此仅称“观察到的仓库版本”。原始 API 响应、图片、清单及 SHA256 保存在本地；公共 JSON 报告保存样本 ID、行号、图片哈希和结果，不上传图片、答案标注或临时下载链接。镜像卡标注的许可不能替代对原始数据来源的核验；扩大使用前应对照 [DocVQA 官方数据说明](https://site.docvqa.org/datasets)。

两轮使用完全相同的图片、问题、参考答案、模型权重和生成参数，仅将整页图片预缩放的最长边上限从 384 调为 512；随后仍使用模型原装 image processor。不是直接修改视觉编码器输入尺寸。

## 结果

| 输入长边上限 | ANLS 风格得分 | 规范化完全匹配 | 生成耗时中位数 |
|---|---:|---:|---:|
| 384 | 0.4844 | 25%（5/20） | 0.625 秒 |
| 512 | 0.7367 | 50%（10/20） | 1.288 秒 |

逐题对照：9 题 ANLS 改善、1 题下降、10 题相同，平均差为 +0.2523。生成耗时只计 model.generate 与设备同步，不含模型加载、图片处理或完整服务开销。未测 MPS 峰值内存，不能据此报告峰值显存。

本实现对文本转小写、去首尾空白并合并连续空白，按归一化编辑距离阈值 0.5 取多参考答案最高分。尚未和官方 evaluator 做逐例一致性校验，因此明确标注 ANLS 风格；规范化 Exact Match 使用相同规范化规则。不能将这里的得分与官方排行榜直接对比。

## 学到了什么

分辨率是当前真实瓶颈之一：同一模型和解码设置下，多道名称、表格和数字题改善。仍有数字错读、答案缺少完整地址、识别错误与冗长回答。ANLS 会给部分相近字符串较高分，例如错误数字也可能得部分分数；因此同时报告完全匹配并保留逐题结果。

部分自由文本答案表达接近参考含义，但因冗长或改写而得分低；这只是错误分析观察，不据此修改参考答案或在预测后使用真值裁剪。题型可重叠，且每类样本很少，题型均分仅作诊断。

本轮证明真实数据零样本基线及分辨率对照能够在 Mac 上运行。尚未证明真实数据 LoRA 增益，也未完成 OCR、证据定位或 7B 训练。下一步准备互不重叠的真实训练和验证文档，固定当前基线条件做 LoRA 前后对照；开发集继续用于诊断，最后另设保留集。
