# 文档区域阅读与分辨率对照 — v0.5.0

2026-10-09，在 VS Code 集成终端使用系统 Python、PyTorch、Mac MPS 完成四组真实文档推理。结论：固定裁剪改善了多图对照，但弱于原装整页单图；整页长边 768 在本开发集上更好。继续以原装单图路径为基线，768 作为待独立验证的候选设置。

## 实验设计

使用 v0.3.0 已查看过的同一批 20 份源文档、20 道题，数据和图片哈希保持一致。固定官方 LLaVA-OneVision 小模型、revision、Float16、无 adapter、greedy、最多 64 个新 token，不修改答案标注。

- 整页 512：一张整页图片，预缩放长边上限 512，使用原装单图 anyres 处理。
- 重复整页三图：三张相同整页图片，每张长边上限 512。
- 固定裁剪三图：依次为整页、上半页、下半页；裁剪原图后，每张长边上限 512。
- 整页 768：原装单图路径，长边上限提高到 768。

两组三图输入使用完全相同的提示、图像占位符数量和嵌套 images=[[image1,image2,image3]] 组织。逐题验证其输入 token 数相同，范围 2227–2244。裁剪函数只读取原图尺寸，不接收问题、答案或区域真值；不挑选题目，不使用真值选择最终回答。

单图和多图的原装图像处理路径不同，所以不能只将三图裁剪与单图作比较，再把全部变化归因于裁剪。重复整页组用于控制三图路径和提示，仍不意味着所有视觉信息量与单图相同。实现依据 [Transformers OneVision 多图说明](https://huggingface.co/docs/transformers/v4.57.1/en/model_doc/llava_onevision#multi-image-inference) 及本机安装的 processor 源码。

## 结果

| 方案 | 规范化完全匹配 | ANLS 风格得分 | 生成耗时中位数 |
|---|---:|---:|---:|
| 整页 512 | 50%（10/20） | 0.73672 | 1.333 秒 |
| 重复整页三图 | 15%（3/20） | 0.40077 | 0.888 秒 |
| 整页＋上下半页 | 35%（7/20） | 0.56096 | 0.912 秒 |
| 整页 768 | 60%（12/20） | 0.83930 | 1.419 秒 |

固定裁剪相对重复整页：8 题 ANLS 改善、1 题退步、11 题相同，平均变化 +0.16019。相对整页 512：2 题改善、6 题退步、12 题相同，平均变化 -0.17576。

整页 768 相对整页 512：4 题 ANLS 改善、0 题退步、16 题相同，平均变化 +0.10258。整页 512 本轮得分与 v0.3.0 同设置结果一致。所有方案保留逐题预测，不只保存改善案例。

## 判断和边界

这轮显示输入组织方式本身会明显影响模型表现。固定局部视图在相同多图路径下有帮助，但目前的简单三图方案不足以超过原装整页路径。不能声称“增加图片数量就提升文档阅读”，也不能根据这个小实验断言所有区域阅读方法都无效。

当前优先验证整页 768 在新的保留文档上的效果，再考虑训练数据扩展或问题相关区域阅读。不会将固定裁剪称为模型原生证据定位；本轮未加入 OCR、学习裁剪器或区域标注。

这是已经用于开发的 20 题顺序子集，不能报告成独立测试或完整 DocVQA 性能。ANLS 为已有明确规范化规则的风格实现，尚未验证官方 evaluator 一致性。生成时间不含模型加载和图片处理；系统温度和执行顺序未严格控制，不能据此作正式速度基准。未测峰值内存，也未验证 768 分辨率训练。
